# LINK?

> 흩어진 피해를, 하나의 사건으로

중고거래 사기를 당한 사람들은 대부분 서로의 존재를 모릅니다.
LINK는 같은 사기범에게 당한 피해자들을 신원을 드러내지 않고 찾아 연결하고, 흩어진 소액 피해를 하나의 사건으로 묶어줍니다.
경찰 제출은 대표 피해자가 직접 합니다.

## LINK는 피해자들을 연결한다

1. 피해자가 사기범의 계좌, 전화번호, 닉네임 같은 단서를 등록하면
2. 같은 단서를 가진 다른 피해자를 찾아 **같은 사기범에게 당한 피해자 인원, 합산 피해액** 을 알려줍니다.
3. 대표 피해자 한 명이 모두의 증거를 모아 **하나의 사건으로 신고**합니다.

## LINK가 바꾸는 것

**혼자가 아니라는 것**
자책하는 대신, 같은 수법에 여러 명이 당했다는 사실을 확인할 수 있습니다.

**작은 피해가 무거운 사건이 된다**
5만 원짜리 사건이 135만 원, 1,350만 원짜리 사건이 됩니다.

**설명 번복 방지**
단서와 증거는 한 번만 등록하면 됩니다. 신고는 대표가 정리된 묶음으로 합니다.

**개인정보 보호**
사기범 단서는 운영자도 원래 값을 볼 수 없게 암호화합니다. 다른 피해자에게 나는 익명으로만 보입니다.
증거는 올리는 순간 봉인되어, 나중에 바뀌었는지 바로 확인할 수 있습니다.

## 실행하기

```bash
npm install
cp .env.example .env.local
npm run dev
```

`.env.local`의 `CLUE_PEPPER`에 아무 문자열이나 넣고(예: `link-demo-pepper-2026`) http://localhost:3000 으로 접속하세요.
이 키는 서버에서만 쓰니 앞에 `NEXT_PUBLIC_`을 붙이면 안 됩니다. 예전 이름인 `NEXT_PUBLIC_CLUE_PEPPER`도 서버에서만 읽어서 그대로 동작합니다.

보안 테스트는 `npm run test:security`로 돌릴 수 있습니다.

- DB 없이 서버 메모리에 저장합니다. 서버를 다시 켜면 데모 데이터(피해자 A~D)로 돌아갑니다.
- 로그인 대신 화면 오른쪽 위에서 데모 유저 A~D를 바꿔가며 씁니다.
- 모바일 화면(폭 390px) 기준으로 만들었습니다.

## 데모 순서

1. `/debug`에서 계좌번호 `110123456789`를 검색합니다. 결과는 0건입니다. 단서는 해시로만, 증거는 `enc:v1:…` 암호문으로만 남아 있습니다.
2. 유저 A의 홈에서는 A, B, C가 한 그룹으로 묶여 있고 합산 피해액은 135만 원입니다. 유저 D는 아직 매칭 대기 중입니다.
   - A는 `110-123-456789`, B는 `110123456789`로 입력했지만 같은 계좌로 인식합니다.
   - B의 `https://safe-pay-check.com/order`와 C의 `www.safe-pay-check.com`도 같은 사이트로 인식합니다.
3. A가 **제가 대표할게요**를 누르고, B와 C로 바꿔 각각 **대표 승인하기**를 누릅니다.
4. B와 C가 **증거 위임하기**에서 "대표가 내 이름과 증거를 보게 됩니다" 안내를 확인하고, 이름을 적어 동의합니다.
5. 다시 A로 돌아와 **증거 묶음 보기**를 엽니다. 맨 위에 착수금·수수료 경고가 있고, 사건 요약과 타임라인, 피해자별 증거가 보입니다. 모든 증거가 `변경 없음 ✓`입니다.
   - **변조 테스트**를 누르면 파일을 1바이트만 바꿔도 `변경됨 ⚠`으로 바뀝니다.
   - B가 같은 주소(`/api/groups/:id/bundle`)로 들어오면 403이 뜹니다.

## 어떻게 동작하나

**단서 정규화** (`lib/normalize.ts`)
같은 단서를 다르게 써도 같은 값이 되도록 맞춥니다.
계좌와 전화번호는 숫자만 남기고 `+82`, `82`는 `0`으로 바꿉니다. 닉네임과 카톡 ID는 소문자로 바꾸고 공백과 앞의 `@`를 지웁니다. 사이트 주소는 프로토콜, `www.`, 경로, 포트를 떼고 도메인만 남깁니다.

**단서 해시** (`/api/clue-hash`)
서버만 가진 키로 `HMAC-SHA256(키, "종류:값")`을 계산합니다. 키는 브라우저 번들에 들어가지 않고, 받은 원문은 저장하지도 로그에 남기지도 않습니다.

계좌나 전화번호는 경우의 수가 적어서, 그냥 SHA-256만 쓰면 가능한 값을 전부 넣어보는 방식으로 원문을 되찾을 수 있습니다. 그래서 비밀키가 있어야 계산되는 HMAC을 쓰고, 키는 서버에만 둡니다. 단서 종류도 같이 넣기 때문에 계좌와 전화번호가 우연히 같은 숫자여도 해시는 다르게 나옵니다.

**피해자 묶기**
해시가 하나라도 겹치는 피해 건을 Union-Find로 묶습니다. 새 피해가 등록될 때마다 전체를 다시 계산합니다.

**익명성**
다른 피해자의 금액, 단서, 이름은 어떤 응답에도 들어가지 않고 `피해자 A · 11월 3일` 같은 카드로만 보입니다.
합산 피해액은 3명 이상 모였을 때만 보여줍니다. 2명일 때 보여주면 합산에서 내 금액을 빼서 상대 금액을 알 수 있기 때문입니다.
예외는 하나입니다. 대표는 위임한 사람의 이름을 볼 수 있습니다.

**증거 봉인과 암호화** (`lib/evidence-crypto.server.ts`)
업로드할 때 브라우저가 계산한 SHA-256을 서버가 받은 파일로 다시 계산해 대조하고, 다르면 거부합니다. 봉인 시각은 서버 시각입니다.
파일은 AES-256-GCM 암호문으로 저장하고, 본인이 볼 때와 대표 화면에서만 복호화합니다.

**접근 제어** (`lib/access.ts`)
그룹 정보는 구성원만, 증거 묶음은 확정된 대표만 볼 수 있습니다. 대표에게는 위임에 동의한 사람의 증거만 갑니다.
남의 피해 건에는 증거를 올릴 수 없고, 이미지가 아니거나 5MB가 넘는 파일은 받지 않습니다.

## 확인한 것

`npm run test:security`와 실행 중인 서버로 직접 확인했습니다.

- `110-123-456789`와 `110 123 456789`는 같은 해시가 나옵니다.
- 다른 계좌, 또는 숫자는 같지만 종류가 다른 단서는 다른 해시가 나옵니다.
- `010-…`, `+82 10-…`, `82…`는 같은 값이 됩니다.
- `https://www…/order`, 대문자, 포트, 경로가 달라도 같은 도메인이 됩니다.
- 카톡 ID `@Seller_Kim`과 `seller_kim`은 같은 값이 됩니다.
- 증거를 1바이트만 바꿔도 해시가 달라집니다.
- 가짜 해시로 증거를 올리면 400으로 거부됩니다.
- `/debug`에서 증거는 암호문으로만 보이고, 계좌번호를 검색하면 0건입니다.
- 대표가 아닌 구성원이 증거 묶음을 요청하면 403이 뜹니다.
- 합산 피해액은 2명일 때 숨겨지고, 3명일 때 135만 원으로 보입니다.
- 빌드된 브라우저 번들에 HMAC 키가 없습니다.
